# editrig-go

Go library: declare an editable entity once — fields, sections, storage cells — publish it as a JSON Schema + uiSchema envelope, and serve load/create/update/delete/options/upload over HTTP. One module, a core with no SQL, driver or locale dependencies, pluggable storage behind hooks. Client side is `@qrotux/editrig-shadcn-react` (React, rjsf v6, shadcn/ui).

## Where to look

- **[README.md](README.md)** — wiring, declaring an entity with `decl`+`ui`+`erjet`, the wire protocol (envelope, error shapes, multipart upload, options), the i18n key convention, the storetest conformance suite. Read the relevant section before touching a public surface.
- **`doc.go`** — the dependency contract of the core, stated in prose and enforced by the import list. Read it before adding any import to the root package.
- **`storetest/storetest.go`** — the behavioural half of the storage contract, the half that is not in the signatures.

## Commands

- Full gate (what CI runs): `test -z "$(gofmt -l .)" && go vet ./... && go test ./...`.
- One package: `go test ./ui/ -count=1`.
- Postgres-backed tests of the shipped store: `EDITRIG_TEST_DATABASE_URL=postgres://user:pass@localhost:5432/db go test ./adapter/erjet/`. They skip when the variable is unset and skip again when the DSN host does not look ephemeral (`localhost`, `127.0.0.1`, `::1`, or a host containing `testdb`/`throwaway`/`ephemeral`) — they run DDL and `TRUNCATE`. Everything else runs without a database.

## Layout

Single Go module. Root package `editrig` is the protocol; every other role is its own package.

- **Root** — `types.go` the `Entity`/`Option*` types, `registry.go` validation at registration, `handler.go` the `Handler` with one method per route and the shared create/update write path, `handler_config.go` the `HandlerOption` set (`WithUnknownFields`, `WithBodyLimits`), `options.go` the options endpoint, `upload.go` multipart decoding, `catalog.go` the i18n seam and key convention, `errors.go` `ErrNotFound` / `ConflictError`, `change.go` the audit report type, `doc.go` the dependency contract.
- **`validate`** — the structural half of validation, usable outside HTTP. `structural.go` JSON Schema validation, `FieldError` and pointer mapping, `write.go` the effective-state overlay for PATCH and the upload markers, `unknown.go` the unknown-field policy, `readonly.go` read-only stripping, `media.go` media-field detection. The root re-exports `FieldError` and `UnknownFieldPolicy` as aliases.
- **`router/erchi`, `router/erstd`** — `Register(r, base, guard, h)` mounts the six routes on chi or on `net/http` `ServeMux`; `router/internal/routertest` is the route contract both pin.
- **`decl`** — the author-facing surface: an ordered `Set[C]` of `Entry[C]` records pairing a form field with a storage cell. `decl.go` the type and its projections (`Fields`, `Order`, `Groups`), `lint.go` the declaration gate.
- **`ui`** — the uiSchema vocabulary. `field.go` the `Field` map with constructors (functions) and modifiers (methods), `ui.go` form-level concepts (`Group`, `Header`, root keys), `wire.go` the `Kind`/`Wire` type axis, `lint.go` the keyword-vs-type gate, one file per field kind (`media.go`, `relation.go`, `items.go`, `list.go`, `icon.go`, `emoji.go`, `geopoint.go`, `document.go`, `iconenum.go`).
- **`adapter/erjet`** — the shipped storage on go-jet + pgx (Postgres). `table.go` the declaration's persistent projection, `store.go` Load/Save/Delete plus the transaction, `column.go` scalar cells, `array.go` array cells, `child.go` child tables, `satellite.go` keyed side tables, `rels.go` relation tables, `deferred_list.go` second-phase lists, `normalize.go` the pgx → JSON value shapes.
- **`storetest`** — the conformance suite any `Store` implementation must pass. `Run` plus the optional `RunSatellite`, `RunExtraTypes`, `RunChildRows`, `RunKeyedChildRows`.
- **`examples`** — `memory` and `postgres`, runnable programs in the same module, each with a test driving CRUD over HTTP. They are documentation that compiles; keep them exercising the public surface only.

Invariants:

- **The core imports only stdlib and `validate`; `validate` imports only `santhosh-tekuri/jsonschema/v6` and `golang.org/x/text`.** No chi, no pgx, no go-jet, no driver of any kind, ever — the core has no route to parse, no transaction to open and no row to scan. chi lives in `router/erchi` alone. Adding a dependency to the root or to `validate` is a design decision to discuss first, never a silent `go get`. `doc.go` states this contract; `go list -deps .` is how you check it.
- **`ui` is a leaf** (`encoding/json`, `fmt`, `sort`, `strings` — nothing else, not even the core). `decl` imports `ui` and `log/slog` and nothing else. `validate` imports neither the core nor `ui`: it takes raw JSON and returns its own `FieldError`, which the core aliases — that is what keeps the core → validate edge acyclic. An adapter imports the core, `decl` and `ui`; a router imports the core; the reverse import would be a compile-time cycle, which is exactly why the boundary holds without policing.
- **The engine knows no locale and no translator.** There is no locale in any signature. It asks a `Catalog` — an interface the application implements — and builds one per request through `Copy(r, entityName)`, substituting only `Entity.Name`. Do not add a locale parameter, a translator func, or a default catalog.
- **The engine knows no storage.** No driver type in any signature; atomicity belongs to `Entity.Save`, which must roll back its own work when it returns `ferr` or `err`. `Entity.Load` reports "no row" as `(nil, nil)`; `Entity.Save` reports it as `ErrNotFound`. Two channels, deliberately different: `Load` needs no core symbol at all, `Save` has only one return path left.
- **The store knows no HTTP and no audit journal.** `adapter/erjet` imports neither `net/http` nor any logging sink. It *reports* what it wrote through `Store.OnWrite`, after a successful commit and only when something changed, in the **core** type `editrig.Change` — so the application writes one bridge to its journal regardless of which store it uses. A store that called the journal itself could not be extracted from the application.
- **The handler knows no router.** `Handler` has one method per route and each takes its route parameters explicitly (`Load(w, r, name, id)`); it never reads a URL param itself. Mounting is a router package's job: `router/erchi` and `router/erstd` are twenty-line `Register(r, base, guard, h)` functions and the only place a router import is allowed. Route topology under `base`, the guard and audit wrapping stay the application's. Configuration is per `Handler` through `HandlerOption` values, never per entity and never through package-level variables.
- **Optional hooks degrade to 405, not to panics or 500s.** `NewRegistry` requires only `Schema` and `Load`. A nil `Save` disables create and update, a nil `Delete` disables delete, the `Disable*` flags do the same for an entity that has the hook; each answers `405 {"error":"method not allowed"}` before any body is read. A nil `Validate` is skipped. A nil `Copy` becomes `PlainCatalog{}`, a nil logger `slog.Default()`.
- **Validation is double and ordered.** Unknown-field policy first (`validate.UnknownFields`), then structural (`validate.Write` over `validate.Structural`), then file injection, then `Entity.Validate`. The order is load-bearing: a media field is declared a string in the schema, so an injected `Upload` would fail structural validation if injected first; and injecting after `Validate` would carry unchecked bytes into the transaction. `Validate` is the only hook with both a catalog and a position before the transaction, and it may mutate `in`.
- **Structural validation sees the effective state; the hooks see the payload.** On update, `validate.Write` overlays the submitted top-level keys on the loaded row (keyed objects merged one level, everything else replaced) and validates that; `Validate` and `Save` receive only what was submitted. Pending uploads are represented in that overlay by markers the schema is widened to accept, so `required`, `minItems`/`maxItems` are checked against the final list without validating an `Upload` as an id string. The markers never leave the validator. Do not pass the overlay to a hook, and do not validate the raw payload alone.
- **Read-only enforcement lives in the engine, and only at the top level.** `validate.StripReadonly` removes every top-level key whose uiSchema entry carries `"ui:readonly": true`, before validation and before `Save` — so `Entity.Save` physically cannot see one. There is no second, root-level list of read-only fields: the flag is declared once, on the field, and derived. Nested keys are *not* stripped, which is why `ChildRows` re-checks item ids against the ones the parent actually owns.
- **The schema is dynamic only at the load/save boundaries.** `Schema(ctx, cat, nil)` is the create form, `Schema(ctx, cat, data)` the edit form; the write path calls it once with the row's current state and reuses that uiSchema for stripping, media detection and structural validation. Do not recompute it mid-request or make it depend on the incoming payload.
- **A field's two halves are one value.** `ui.Field` is a single map split by the `ui:` prefix at marshal time (`Split`), never two parallel declarations. Modifiers are copy-on-write methods; constructors are package functions. Markers (`requiredKey`, `itemsKey`, `keyedItemsKey`) never reach the wire — `Document.Marshal` turns the first into the root `required` array and the others into structure.
- **The wire-shape axis is read from the keys that actually travel.** `Field.WireKind` derives `ui.Wire` from the same map that becomes the schema, and `Column.Accepts` answers from the same cell that does the parsing. Never introduce a third list of shapes; it is the exact defect `Field` exists to prevent.
- **Declaration defects panic or lint at declaration time, never at request time.** `ChildTable.requireColumns` panics for a missing `ID`/`Parent`/`Order`; `ChildValues`/`ChildRows` panic unless `ChildTable.Key` is nil and `KeyedChildValues`/`KeyedChildRows` panic unless it is not; `ChildValues` panics on a cell with no `value` or a non-column projection. `decl.Lint` and `ui.Lint` are run from a test of the entity, not from a handler: every finding is permanently present or permanently absent in the code.
- **`storetest` is the storage contract.** A behaviour a store must have goes into the suite, not into a comment. Adding a required behaviour to `Run` obliges every implementation; a behaviour only some backends can have gets its own optional sub-suite (`RunSatellite`, `RunExtraTypes`, `RunChildRows`, `RunKeyedChildRows`) called in addition to `Run` by the implementations that support it. Fixture field names are exported constants so a typo is a compile error.
- **`erjet.Save` is a partial update.** The SET list is the intersection of the payload with the writable cells of the declaration: an absent key leaves its column untouched, an explicit JSON `null` becomes an explicit SQL NULL. A cell that cannot parse the incoming shape returns `ok=false` and its column is skipped — which is precisely why `decl.Lint`'s type axis exists, because that failure is silent.
- **Limits are constants next to the code that enforces them** — `uploadMaxBytes` and `multipartMemory` in `upload.go` are the defaults `BodyLimits` falls back to (with 4 MiB for JSON), `optionsDefaultLimit`/`optionsMaxLimit` in `options.go` — and they are documented in README. Change both together. `MultipartMemory` is a memory/tempfile threshold, not a size limit; only `http.MaxBytesReader` bounds the body. Zero in `BodyLimits` means default, negative panics at construction.
- **Identifiers are strings on the wire, whatever the column.** `erjet` accepts text, uuid and integer primary, child, parent and relation keys; every id is read back through `normalizeIdentifier` as an exact decimal or uuid string and compared via `::text`. Never route an id through `float64`: a bigint above 2^53 would silently change.
- **Cross-language constants are mirrored, not imported.** `ui.MediaFieldKey` and the core's unexported `mediaFieldKey`; `ui.SubfieldSuffix` and `editrig.FieldKey`; `ui.GroupsKey`/`HeaderKey` and their TS counterparts. The core does not import `ui` by contract, so each side holds the literal once. Change one, change the others — a drift gives a silent fallback (the raw key rendered as a label), not an error.
- **The wire format is the contract.** Handler tests pin exact status codes and error bodies, `Document.Marshal` tests pin key names and omitted keys, store tests pin value shapes. Do not loosen an assertion to make it pass; if the shape changes, the client changes too.

## Comments in code

Comments in this repository are currently written in Russian and are being translated to English; write every new or edited comment in English.

- **Criterion:** a comment is justified only when it carries what the code does not show.
- **Write:** non-obvious invariants; library and database gotchas (rjsf routes `ui:widget` only for leaf schemas, ajv reads `enumNames` only from the uiSchema, `ParseMultipartForm`'s maxMemory is not a size bound, go-jet needs an explicit cast for enum and uuid parameters, pgx value shapes); reasons behind counter-intuitive decisions; "breaks if…"; what a test pins.
- **Do not write:** a paraphrase of the signature, a list of fields, a narration of obvious code. Exception — the doc comment of an exported Go symbol: convention requires it and it starts with the name (`// FooBar …`), one sentence, no parameter listing.
- **Present tense only.** No "was X → now Y", no tombstones for deleted code — history lives in git. No TODOs at all: a plan for later is a tracker task, not a comment.
- **Never reference:** plan documents (`Task N`, waves, phases, `spec §N`), commit hashes, dates of decisions, or the repository this code was extracted from — no `internal/admin/...` paths, no "port of", no "mirrors upstream".
- **May reference:** external standards (JSON Schema, RFC 3339, GeoJSON, rjsf and pgx behaviour), README.md, live files of this repo.
- **Length:** one or two sentences; collapsing twelve lines into one is normal. Nothing left to say — delete the comment.
- **Subagents:** include these rules in the brief of every subagent that writes or edits code.
- **Reading someone else's comments:** a comment is not the source of truth. When editing code, check its comment against the code; if it lies, fix or delete it. Verify facts about storage against the queries, not against prose.

## Coding

- **Copy the pattern, do not invent:** before a new field kind, cell, handler or conformance check, find the nearest existing analogue and repeat its shape — constructor vs modifier, where the gate panics, which test pins it.
- **A new field kind is two halves and a gate.** A `ui` constructor, the cell that parses it in `adapter/erjet`, and their agreement on the `ui.Wire` axis (`WireKind` / `Accepts`), plus whatever `ui.Lint` must now know about its keywords. A half without its counterpart is a field that renders and never saves.
- **Diff discipline:** no renames, no file moves, no drive-by refactors, no backward-compatibility shims or fallbacks nobody asked for.
- **Tests as a ladder, not after every minor step.** During a task — `go build ./...` plus the tests of the touched package. The full gate only at boundaries: end of task, before a commit, before saying "done". The Postgres suite skips by default, so a green `go test ./...` is not evidence that the store still works — run it with `EDITRIG_TEST_DATABASE_URL` before claiming a store change is done (`examples/postgres` skips on the same variable). CI has no database service and must stay that way; the Postgres run is local, on a throwaway container.
- **Docs move with the public surface.** A change to an exported API, a field kind, a cell, a limit, an error shape or a route contract updates README.md in the same change.
